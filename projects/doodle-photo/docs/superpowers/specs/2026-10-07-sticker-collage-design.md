# 抠图贴纸拼贴设计

日期：2026-10-07
状态：用户已于 2026-10-08 确认本设计；进入实施计划评审。

## 目标与已确认需求

在 Doodle Photo 中增加「贴纸拼贴」模式。用户上传多张照片，系统自动抠出每张照片的主要主体，生成带白色描边的透明贴纸，自动排成一张海报；用户随后可以调整贴纸和手绘元素并导出 PNG。

参考图的主要视觉特征是保留真实照片质感的独立主体、白色实线或虚线外描边、错落的大小与角度、手写标题和少量线稿装饰。参考图用于指导拼贴效果，不作为界面截图逐像素复刻。

用户已确认：

- 自动抠图并排版，再允许手动调整。
- 背景同时支持照片和纸张／纯色。
- 每张照片默认提取一个主要主体。
- 默认 3:4 竖版，支持调整描边、拖动、缩放、旋转、层级、删除、撤销和 PNG 导出。

第一版采用浏览器内的单次作品状态；不引入账号、云端素材库、作品持久化或额外图像生成服务。单个作品最多 16 张静态 JPG／PNG／WebP（包含处理中与失败的素材，删除素材卡后释放名额），每张最多 20 MiB，解码像素最多 4000 万。背景照片单独上传，适用相同文件限制，不消耗贴纸名额。导出尺寸为 1080 × 1440 像素。

## 路线选择

可选路线及取舍：

1. **独立拼贴模式，复用分割与绘制能力（采用）**：多图素材、画布和请求队列有独立状态；现有文字、线稿、几何约束可以共用。
2. **在当前单图编辑器中加入多图状态**：入口集中，但背景图尺寸、原图主体坐标和贴纸画布坐标会混在一起，修改范围较难控制。
3. **先建设独立贴纸素材库，再进入拼贴**：适合跨作品复用，需新增素材存储、资源管理和加载流程，超出当前单次制作海报的目标。

## 用户流程

### 入口与上传

首页提供「照片手账」和「贴纸拼贴」两个模式入口。拼贴模式显示多选上传区域，支持点击选择和拖入多个文件。

每张照片有一张素材卡，显示缩略图、文件名以及「等待中／抠图中／可用／失败／已取消」状态。上传前检查格式、大小、张数；无效文件逐张提示，合法文件继续处理。损坏图像和动画图片明确拒绝，不静默选取动画首帧。

首次批次处理结束后，用所有成功素材生成初始拼贴。部分照片失败时，成功素材仍可生成和导出；全部失败时保持素材卡和重试操作，不生成空白成功作品。

### 自动抠图与纠正

每张照片识别一个明确的主要主体，可包含同一主体的多个分离区域。不能简单取现有完整主体清单的第一项，也不能把照片中的所有主体合并成一张贴纸。

素材卡提供「重试」和「纠正抠图」。纠正窗口展示经 EXIF 方向修正后的原照片，允许重新框选、添加主体点和背景排除点，再生成贴纸。手动提供完整几何提示时只调用 SAM，不额外请求视觉模型。

首次纠正成功后添加可用贴纸；替换已有贴纸时保留该元素的中心、宽度、角度和层级，根据新贴纸比例重算高度并约束边界。失败保留上一版可用贴纸。替换作为一次可撤销操作。

### 背景与自动排版

画布固定为 3:4，初始使用深灰纸张背景，以便白色线稿清晰可见。背景选项包括深灰纸张、米白纸张、自定义纯色和上传照片。纸张纹理用确定性的前端绘制生成，不请求图像服务。背景照片按 cover 居中铺满，可以拖动调整裁切位置。

首次自动排版保留顶部标题区域、四边安全距离和装饰留白。根据素材数量与长宽比生成疏密不同的布局，使用稳定的小幅位置偏移和旋转形成错落感。优先保留主体完整性，不裁切贴纸来填满格子。

自动排版必须放入全部成功素材，并将贴纸描边、旋转后的完整可见范围计入边界和重叠检查。数量较多时缩小贴纸，文字和装饰无安全空位时减少或省略，不能挤占主体。

自动生成一个可编辑标题、最多四条短句和最多八个手绘装饰。按素材的主题与文案选择现有线稿；标题没有可靠主题时使用「把日常，贴成一页」。深色背景用白色文字和线稿，米白纸张用深棕色；自定义纯色按亮度选择，照片背景默认白色并提供深色／浅色手绘切换。

用户编辑后，后续新增素材只放到可用位置，不自动打乱已有元素。如果找不到安全空位，素材卡明确显示「待放置」，允许手动添加或点击「重新排版」，不能无提示地遗漏成功素材。所有素材处理结束后，可以点击「重新排版」统一生成布局；此操作可以整体撤销。背景切换和素材重试不会隐式触发重新排版。

### 手动编辑与导出

贴纸、文字和装饰可以选择、拖动、等比例缩放、旋转、置顶、置底、删除。素材卡提供明确的贴纸选择入口，解决重叠和透明区域的选择问题。

贴纸支持白色实线／虚线／无描边，描边宽度 0–16 个导出像素，默认实线 6 像素。描边作为显示效果独立于主体 PNG，不修改真实 alpha。样式修改、替换、增删、拖拽、文本编辑、层级和重新排版都纳入最近 20 步撤销；一次拖拽或连续输入算一次操作。

预览和导出调用同一个画布绘制函数。导出等待字体、背景和贴纸图像解码完成，输出 1080 × 1440 PNG；控制框、处理提示、素材卡不进入导出图。导出期间冻结本次状态快照，失败显示可重试错误。

## 前端结构与状态

- `App.jsx`：模式入口，挂载独立的 `CollageStudio`。
- `CollageStudio.jsx`：素材、处理队列、背景设置、作品状态和撤销历史。
- `MultiImageUploader.jsx`：多选、拖入、验证、缩略图解码和逐张错误。
- `CollageCanvas.jsx`：响应式画布、元素选择与编辑控件。
- `CollageSubjectCorrection.jsx`：复用现有框选及正负点几何工具，针对素材调用抠图接口。
- `collage-layout.js`：从可用素材创建确定性布局，不复用「避让原图主体放装饰」的现有布局算法。
- `image-stickers.js`：解码并缓存透明 PNG，生成描边显示缓存。
- `collage-renderer.js`：绘制背景，再按元素数组顺序绘制贴纸、文字和装饰；供预览和导出共用。

复用 `journal-layout.js` 的旋转边界和约束函数，为贴纸增加描边外扩范围。元素使用现有 0–1000 的中心位置与尺寸坐标，`aspect` 始终取目标拼贴画布的高宽比。

从 `journal.js` 抽取可单独绘制手绘元素的入口；现有 `drawJournal()` 继续通过该入口绘制单图手账。文字与线稿可指定颜色，未指定时保持现有默认值。仅做支撑新工作流的抽取，不重写单图主体排版。

作品元素为可克隆的普通数据：

```text
{ id, type: "imageSticker", assetId, sourceId,
  x, y, width, height, rotation, aspect,
  borderStyle, borderWidth }
```

原始文件、缩略图、解码后的图像与描边缓存放在素材存储中，不嵌入元素数组。每次成功抠图产生新的 `assetId`，同一原照片保持稳定的 `sourceId`；旧资产在仍被画布或撤销历史引用时保留。移除引用后释放对象 URL 和缓存。

每个素材请求有独立的版本号和 AbortController。前端最多同时发出两个抠图请求。重试、删除、离开拼贴模式或重置作品时取消相应前端请求并使旧结果失效；已发出的后端计算可能继续，但返回结果不得写入新作品。切换模式保留完成的作品，未完成素材标为可重试的「已取消」。

## 后端抠图接口

新增同域 `POST /api/cutout`，继续使用项目已有的 Moonshot 配置和 SAM 权重，无须新增服务或密钥。

multipart 参数：

| 参数 | 含义 |
| --- | --- |
| `file` | 一张受文件及像素限制约束的静态照片 |
| `subject` | 可选的主体标签、`box_2d`、分割区域和正负提示点 JSON；坐标归一化到经 EXIF 修正的完整原图，范围 0–1000 |

未提供 `subject` 时，使用专用提示词识别一个主要主体、主体框、前景／背景提示点、主题及简短文案。对模型返回和请求提交的几何，先严格检查结构、有限数值、0–1000 范围、主体框正面积和点位数量，再复用现有几何归一化函数；无效值返回 422，不能借现有函数截断越界坐标或静默丢弃坏点。提供 `subject` 时直接验证并运行 SAM，不请求视觉模型。

从现有 `extract_contour_rings_with_sam()` 抽出「推理并选取真实 mask」函数。描边继续从选中的 mask 提取外轮廓；抠图直接使用像素 mask，不从轮廓多边形重建透明度。同一主体的多个可信区域按像素并集合并，区域有任何不可靠结果时本次抠图失败，交给用户纠正，避免默默丢掉主体部件。

图像统一进行 EXIF 转正，先保留原图 RGB 与 alpha，再独立构建 SAM 的 RGB 输入。视觉定位在最长边 1536 以内的完整工作图上进行；几何结果回到原图坐标。SAM 使用全部分割区域的联合主体框外扩约 20% 的局部裁切，裁切最长边同样最多 1536，并映射提示点；不能直接使用只裁一个 region 的现有裁切函数来处理多区域主体。局部裁切边缘不能截断任何给定主体框；分割结果映射回原图后按实际非零 alpha 范围裁切。

输出贴纸最长边最多 1536。颜色使用对应的真实照片像素，alpha 来自 SAM 的二值像素掩膜；缩放只进行常规插值，不增加语义部件、填平孔洞或伪造细节。原图已含 alpha 时，输出 alpha 与原 alpha 相交，避免重新填入原透明区域。SAM 质量选择规则继续拒绝与前景／背景提示冲突或明显外泄的结果。

成功响应：

```text
{
  status: "success",
  data: {
    image: "data:image/png;base64,...",
    width, height,
    original_width, original_height,
    crop_box: [left, top, right, bottom],
    subject: { label, box_2d, segmentation_regions },
    caption, theme, emotion,
    contours, quality
  }
}
```

`width/height` 是 PNG 像素尺寸；`original_width/height` 是 EXIF 修正后的原图尺寸；`crop_box` 为原图像素坐标。`contours` 是输出 PNG 局部像素坐标的外轮廓，供虚线边框显示，不参与重建 alpha。轮廓总点数限制为 16384；显示轮廓简化不能改变 PNG alpha。`quality` 是分割质量信息，不作为主体名称识别准确率。

CPU 工作通过 `run_in_threadpool` 执行。当前 SamPredictor 有图像内部状态；新旧接口共用 `_sam_lock`，从 `set_image` 到本次所有预测及 mask 复制保持在锁内。视觉请求不持有 SAM 锁。锁外执行 PNG 编码。前端并发上限不能替代后端锁。

接口保留真实 HTTP 失败状态：400（无法解码或不支持格式）、413（文件或像素超限）、422（几何无效、没有明确主体或无可靠掩膜）、503（SAM 未加载或自动识别缺少配置）、502（视觉服务失败）。未知异常显式返回 500，不通过现有全局处理器变成 HTTP 200 成功响应。

不把上传照片或透明 PNG 保存到服务器磁盘，不新增可公开访问的素材 URL。复用现有照片发送到配置视觉服务的处理方式。

## 验证与验收

### 离线测试

- 用有孔洞、细小分离部件和明显背景的合成 mask 验证 PNG alpha 的真实保留；裁切坐标、EXIF 转正和区域坐标映射正确。
- 验证无可靠 mask、配置缺失、上游失败、无效文件及越界几何返回对应错误；不能以空 PNG 或矩形裁剪作为成功结果。
- 验证共用 predictor 在不同照片间不会混用图像状态，既有描边测试继续通过。
- 对 1、2、4、9、16 张不同长宽比素材验证自动布局：成功素材不遗漏，旋转与边框不越界，标题和主体不互相覆盖。
- 验证素材替换与删除后的撤销仍能恢复旧资产；取消／重试后的旧结果不得覆盖新素材，新增素材不得改写已编辑元素。

### 界面与视觉验证

- 使用至少三张真实照片走通「多图上传→抠图→自动排版→编辑→PNG 导出」。记录实际接口、分割效果和耗时；模型或服务不可用时明确区分离线验证与真实接口验证。
- 检查 16 张照片、横长主体、竖长主体，以及一张失败而其余成功的场景；不得出现主体被排版裁断或整个作品无法使用。
- 检查深灰纸张、米白纸张、自定义纯色和照片背景，文字可见，实线／虚线描边与导出一致。
- 验证鼠标与触摸拖拽、缩放、旋转、层级、文字修改、纠正、重试、撤销和背景裁切调整。
- 在桌面宽度及窄屏宽度检查上传区、素材卡与编辑控件可用，导出图不含操作控件。
- 运行 `npm run lint`、`npm run build`、现有 JavaScript 单元测试与 Python 后端测试，并保存拼贴预览和导出证据。

## 已知边界

SAM 二值分割不保证毛发、半透明物体、严重遮挡或照片外被截断的部件精确。纠正可以改善主体选择和误纳入背景；不能恢复原图没有的内容。1536 像素的分割工作上限限制边缘精细度，导出不宣称原照片全分辨率抠图。

多图耗时随照片数量和 CPU 性能增加。界面逐张显示进度，允许取消和逐张重试，不承诺固定完成时间。第一版不保存跨刷新作品，也不支持逐张贴纸文件下载、额外画布比例或批量作品生成。
